Fluxo em Python

Do cálculo à publicação

A pasta BETA_PYTHON/ traduz os scripts do Earth Engine para a API Python. Com ela, os módulos são recalculados, validados contra o que já foi publicado e promovidos para a pasta pública.

1 · calcular

modulo1.py … modulo4.py

Os estágios de cada módulo. Nas extensões, os estados internos (idades, estoques, acumulados) são recalculados em memória.

2 · exportar

export_beta.py

Monta os exports. Roda em dry-run por padrão e recusa sobrescrever um asset existente.

3 · validar

validate*.py · lineage.py

Faz as regressões: grafo idêntico ao código anterior, histórico idêntico ao publicado e reprodução do ano anterior.

4 · publicar

promote.py

Copia para public/ccal_02 com checagem de linhagem e mantém a cópia na pasta da versão.

5 · resumir

statistics_ccal.py

Soma por bioma × UF × ano. Alimenta a página de estatísticas e o Looker Studio.

Versões “.1” e “.0”

  • “.1” (extensão): acrescenta um ano novo com o mínimo de reprocessamento. O histórico é relido da versão publicada, e o asset público é sempre um raster stack completo com todos os anos.
  • “.0” (versão cheia): reprocessa a série inteira com fontes atualizadas e remove os remendos das extensões.

Rodando localmente

Na raiz do repositório, com um ambiente que tenha earthengine-api:

python -m BETA_PYTHON.auth --login <perfil>
python -m BETA_PYTHON.export_beta --project <projeto> --modules m3x        # dry-run
python -m BETA_PYTHON.statistics_ccal extract --submit
python -m BETA_PYTHON.statistics_ccal download && python -m BETA_PYTHON.statistics_ccal build
python -m BETA_PYTHON.site_estatisticas

As credenciais ficam fora do repositório (%APPDATA%/CCAL/credentials/). Veja BETA_PYTHON/README.md.
